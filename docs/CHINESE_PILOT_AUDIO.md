样板使用 `zh-CN-XiaoxiaoNeural` 普通话女声，合成速度固定为 `-8%`，网页播放速率为 `1`。录音只覆盖第1课《大青树下的小学》和第4课《古诗三首》的核对词语、会写字的组词提示，以及三首公版古诗的分行朗读。不会把现代课文的长段正文制作成新录音。

## 内容源与正音

`src/data/chinesePilotClips.json` 是唯一内容源。每个条目使用稳定 ID，保存显示文本、实际合成文本、经过内容核对的拼音和来源。显示与合成文本通常相同；如以后因正音而采用同音替代，应显式填写 `spokenText` 并记录理由，不能悄悄改动孩子看到的教材文本。

认读题直接比较汉字和拼音，不给孤立的多音字使用系统默认朗读。会写字听写使用核准组词的整词录音，词语听写读完整词语，古诗按完整诗行合成。需要复听的重点包括：相和的“相” `xiāng`、未磨的“磨” `mó`、石径斜的“斜” `xié`、挑促织的“挑” `tiǎo`，以及词语中的轻声、变调。拼音标注使用字典规范声调，实际普通话朗读中的连续变调不应作为拼音题错误。

内容核对与声音审听分别记录。MP3 的解码、音量和文件完整性验证不能证明每个多音字或韵律已经通过教师审听；在获得家长或老师反馈前，不标记为“教材原声”或“全部人工审听通过”。

## 资源合同

- `public/audio/chinese-pilot/`：静态 MP3 与完整 `manifest.json`。
- `src/data/chinesePilotAudioManifest.json`：与公开清单的 `schemaVersion`、`voice`、`rate`、`locale`、`source`、`entries` 字段保持一致，供前端导入。
- `entries[clipId]`：至少包含 `id`、`file`、`text`、`spokenText`、`durationSeconds`、`bytes`，并保留源清单的拼音与来源字段。
- 公开清单的 `files[file]`：记录 SHA-256、文件字节、时长、采样率、峰值与 RMS 音量。

文件名由声线、语速、合成文本与处理版本的 SHA-256 前24位生成。同一文本供多个题目复用同一 MP3。前端地址应在 `file` 前添加 `import.meta.env.BASE_URL`，兼容 GitHub Pages 仓库路径。

音频处理采用单声道24 kHz、128 kbps MP3，统一 `loudnorm=I=-18:TP=-2:LRA=7`；只收短片段两端的过长静音，保留诗句内部停顿。现有英语词语和活动的所有 MP3、脚本、清单都不改动。

播放器必须由点击启动，切题、切课程、退出或卸载时停止并解绑旧音频；加载失败时允许重试，不能偷偷切到系统 TTS，也不能因为点过播放按钮就记录听写正确。

## 生成与离线验证

在仓库根目录执行，使用原有固定依赖：

```powershell
python -m venv output/chinese-audio-env
output/chinese-audio-env/Scripts/python.exe -m pip install -r scripts/requirements-audio.txt
output/chinese-audio-env/Scripts/python.exe scripts/generate_chinese_pilot_audio.py
output/chinese-audio-env/Scripts/python.exe scripts/generate_chinese_pilot_audio.py --verify-only
```

原始合成、中间 WAV 和探测样例保存在被 Git 忽略的 `output/chinese-pilot-audio-build/`，不会随网页发布。生成器默认最多三个请求并行，每段最多重试三次；`--concurrency 1` 可降低并发。已校验的 MP3 直接复用。全部文件准备好后才更新两份清单。

`--verify-only` 不联网，检查文本 ID 精确覆盖、两份清单一致、源字段未变、每个 MP3 完整解码、SHA/时长/字节正确、合理音量，以及没有丢失或未引用的 MP3。脚本不会提交 Git 或发布网页。
